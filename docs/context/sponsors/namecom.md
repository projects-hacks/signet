## The challenge

Build a product powered by the name.com API, using domain search, availability
checks, registration or DNS management as a core part of the build. Format is
open, new build or extension, as long as the API is functionally central.
Judges want the API doing something the product actually depends on.

## Judging criteria, the most explicit of any sponsor

| Criterion | What they want |
|---|---|
| API integration depth | How central the API is. Favours integrations combining several endpoints, search plus registration plus DNS, over one surface level call. |
| Creativity and originality | Favours unexpected applications over incremental tweaks on existing domain search tools. |
| Technical execution | Code quality, architecture decisions, edge case handling. |
| Real world viability | Could this plausibly become a product people use. |
| Presentation and demo | Wants the integration in action, not slides. |
